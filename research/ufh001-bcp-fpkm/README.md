# Methods and interpretation

The [sample manifest](sample_manifest.tsv) maps the nine matrix columns to GEO sample accessions, dose arms, and the three controls reused from GSE123856. The [analysis](analysis.py) reads the checksum-pinned FPKM matrix, checks all cells for finite nonnegative values, and verifies a one-to-one approved HGNC Entrez-to-Ensembl crosswalk against a pinned HGNC source snapshot. Ambiguous mappings are excluded. It computes sample sums and detection counts, pairwise Pearson correlations over log1p(FPKM), and separate group-mean ratios for the 20 µM and 200 µM arms against the shared vehicle controls. Ratios are shown with 0.1 and 1.0 FPKM pseudocounts. A feature enters the twofold tally when mean FPKM is at least 1 in any arm.

These are descriptive summaries of processed bulk expression. No statistical model, adjusted p-value, gene-set enrichment, cholesterol flux, receptor binding, or genetic target perturbation was run. Both dose contrasts share controls. The source paper's HMGCR intervention is reported as external evidence rather than a result of this notebook. A controlled cross-cell experiment would need matched exposures and genetic perturbations to identify context or target interactions.

The [report specification](report-spec.json) labels every report claim as observed, source-reported, or proposed and points observed claims to executed notebook artifacts. The [generation receipt](generated/generation-receipt.json) binds source inputs, notebook, results, and report hashes.
## Raw-read reanalysis input

The [raw-run manifest](raw_run_manifest.tsv) maps GEO sample accessions and deposited FPKM columns through BioSample and SRX to nine ENA single-end FASTQs totaling 9,848,268,877 bytes. The GEO links came from the [GSE125511 family SOFT record](https://ftp.ncbi.nlm.nih.gov/geo/series/GSE125nnn/GSE125511/soft/GSE125511_family.soft.gz), and file lengths and MD5 values came from the [ENA run report](https://www.ebi.ac.uk/ena/portal/api/filereport?accession=PRJNA516651&result=read_run&fields=run_accession,sample_accession,experiment_accession,fastq_ftp,fastq_bytes,fastq_md5&format=tsv), retrieved 2026-10-26. The three DMSO libraries are the same control samples reused in GSE123856, not independent replication. Those ENA MD5 values remain source-reported; this project's FASTQs were converted independently from checksum-verified NCBI SRA archives. A count reanalysis with a pinned GRCh38 annotation is still needed before inference or cross-study comparison.

The [NCBI SRA manifest](sra_run_manifest.tsv) records the same nine runs as normalized SRA objects with source MD5 values from the [NCBI SRA Data Locator](https://locate.ncbi.nlm.nih.gov/sdl/2/retrieve?acc=SRR8477804&meta-only=yes). It keeps the reused-control identity explicit. [fetch_sra_inputs.py](fetch_sra_inputs.py) retrieves each archive and verifies its length and MD5, including a check that all three reused controls remain labeled as such. [convert_sra_to_fastq.py](convert_sra_to_fastq.py) verifies the archives again, converts them with NCBI fasterq-dump, checks read counts against the source manifest, measures minimum and maximum read lengths across each FASTQ, and writes FASTQs with pigz 2.8 (`-n -1 -p 4`) and a source-hashed conversion receipt. The command omits filename and timestamp from the gzip header, and each receipt records the compression version and settings. ENA reports single-end layout but leaves `nominal_length` blank, so a later STAR index must use the measured maximum read length. Run `python research/ufh001-bcp-fpkm/fetch_sra_inputs.py --workers 6` and then `python research/ufh001-bcp-fpkm/convert_sra_to_fastq.py` from the repository root. These scripts do not establish gene expression results until alignment and a count notebook have been executed and reviewed.

The [completed conversion receipt](results/raw_counts/conversion_receipt.json) binds the nine per-run sidecars and FASTQ SHA-256 hashes to the source manifest and conversion script. All nine libraries match their expected read counts, totaling 226,737,801 reads; each has a measured read-length range of 35–76 nt. The compressed FASTQs and SRA archives are excluded from Git. Conversion alone does not establish gene expression results.

[fetch_reference.py](fetch_reference.py) retrieves the GENCODE v48 GRCh38 primary-assembly FASTA and GTF and checks their published MD5 values. [reprocess_star_counts.py](reprocess_star_counts.py) builds a STAR 2.7.11b index with suffix-array sparsity 8, a 12 GB generation cap, and the maximum observed FASTQ read length minus one for `sjdbOverhang`, aligns all nine libraries, and writes per-library mapping QC plus deterministic compressed integer gene-count and annotation tables. It checks the three reused-control identities against both the SRA and sample manifests. The result receipt hashes the scripts, manifests, conversion receipt, and output tables. Large reads, reference, and index files remain outside Git. Run these steps after the SRA conversion:

```sh
python research/ufh001-bcp-fpkm/fetch_reference.py
python research/ufh001-bcp-fpkm/build_star_patched.py
python research/ufh001-bcp-fpkm/reprocess_star_counts.py
```

The STAR build pins the 2.7.11b source archive by SHA256 and initializes `transform.outQuant` before compilation. This addresses the [upstream `/geneInfo.tab` GeneCounts bug](https://github.com/alexdobin/STAR/issues/1953) observed on Apple Silicon. The processing receipt records the patched binary SHA256. On macOS, the build requires Homebrew GCC 15; on Linux it uses GCC and make.

This raw-count workflow is specified but not yet executed. Neither a differential-expression model nor a cross-cell replication claim is justified by the processed FPKM audit.

The [raw-count notebook](../../notebooks/terputer-ufh001-bcp-raw-counts.ipynb) is a prespecified, unexecuted PyDESeq2 0.5.4 analysis. It checks the processing receipt and library identities, reviews mapping and sample correlations, then fits one `~arm` model with separate 20 µM and 200 µM contrasts against the shared controls. Its dependency environment is pinned in [requirements-raw-counts.lock.txt](../../requirements-raw-counts.lock.txt). Both contrast tables must be interpreted with the reused controls and per-contrast FDR adjustment in view; neither is an independent replication of the other.

When all nine libraries have passed mapping QC, run `python research/ufh001-bcp-fpkm/run_raw_count_notebook.py` from the repository root in that environment, or launch the same script with Terputer's `start_research_job` tool and poll `get_research_job`. The wrapper declares the processing receipt, count tables, QC, manifests, and analysis script as notebook inputs; it declares both contrast tables, summary, QC, and figure as outputs. The resulting `research/execution-receipts/terputer-ufh001-bcp-raw-counts.json` binds them for report generation and curated gene-effect export. The existing white paper remains descriptive until the execution receipt and QC are reviewed.
